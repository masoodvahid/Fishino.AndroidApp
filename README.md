# اپ اندروید فیشی‌نو

یک اپ برای همه مشتری‌ها. هر کارمند در اولین اجرا **کد ۶ رقمی کارفرما** را وارد می‌کند، اپ از «سامانه مدیریت راهکار دیجیتال شریف» نام کارفرما و آدرس API نصب اختصاصی او را می‌گیرد، کاربر نام را تأیید می‌کند و آدرس برای همیشه ذخیره می‌شود.

- **تکنولوژی:** Kotlin، Jetpack Compose (Material 3)، DataStore، OkHttp، kotlinx.serialization
- **حداقل اندروید:** 7.0 (API 24) — راست‌به‌چپ، فونت وزیرمتن

---

## جریان اتصال به کارفرما

```text
کد ۶ رقمی ──► POST https://api.rahkar-digital.ir/api/v1/app/resolve
                  {code, product: "fishino", challenge}
             ◄── نام کارفرما + آدرس API، داخل توکن امضاشده (Ed25519)
اپ امضا را با کلید عمومی ثابت‌شده در اپ بررسی می‌کند
        ──► «آیا کارفرمای شما … است؟» ──► تأیید ──► ذخیره در DataStore
```

- کد کارفرما همان **کد لایسنس** در سامانه مدیریت است و آدرس API از **آدرس سامانه** همان لایسنس ساخته می‌شود (`app_url` + `/api/v1`). لایسنس بدون آدرس سامانه از اپ قابل اتصال نیست.
- اپ فقط به محتوای توکن امضاشده اعتماد می‌کند و `challenge` هر درخواست را در آن بررسی می‌کند؛ پاسخ دستکاری‌شده یا تکراری (مثلاً از پروکسی یا شبکه آلوده) پذیرفته نمی‌شود.
- فقط آدرس‌های https پذیرفته می‌شوند.

## تنظیمات قبل از اولین بیلد

در `gradle.properties`:

| کلید | مقدار |
|---|---|
| `fishino.directoryUrl` | آدرس API سامانه مدیریت، با `/` در انتها |
| `fishino.productSlug` | شناسه (slug) محصول فیشی‌نو در صفحه «محصولات» سامانه مدیریت |
| `fishino.directoryPublicKey` | مقدار `data.public_key` از `https://api.rahkar-digital.ir/api/v1/public-key` (در صفحه هر لایسنس هم هست) |
| `fishino.updateRepo` | مخزنی که اپ از آخرین Release آن به‌روز می‌شود (`owner/name`)؛ خالی = غیرفعال |

بدون کلید عمومی، ساخت APK با پیام خطا متوقف می‌شود (تست‌ها اجرا می‌شوند). اگر کلید امضای سامانه مدیریت عوض شود، باید نسخه جدید اپ منتشر شود.

## اجرا

```bash
./gradlew testDebugUnitTest   # تست‌ها
./gradlew assembleDebug       # app/build/outputs/apk/debug/app-debug.apk
```

یا پروژه را در Android Studio باز کنید. GitHub Actions روی هر push تست‌ها را اجرا می‌کند و نسخه تست (`fishino-test-apk`) را به‌عنوان Artifact می‌سازد.

## ورود کاربر

پس از تأیید کارفرما، صفحه ورود نیتیو نمایش داده می‌شود؛ همان دو روش نسخه وب:

- **نام کاربری و رمز عبور**
- **کد پیامکی**: کد از پنل پیامک همان کارفرما ارسال می‌شود (۵ رقم، ۱۰ دقیقه، یک‌بارمصرف). اپ پیامک را با «SMS User Consent» گوگل می‌خواند: اندروید پیام را نشان می‌دهد و با یک «اجازه» کد پر و ورود انجام می‌شود (بدون مجوز پیامک و بدون تغییر قالب پیامک). روی گوشی‌های بدون سرویس‌های گوگل، کد دستی وارد می‌شود.

API ورود در خود فیشی‌نو است (`/api/v1/auth/...`، از نسخه‌ای که این API را دارد). مقابله با ربات سمت سرور انجام می‌شود: پس از ۳ خطا کپچای عددی، پس از ۶ خطا قفل ۱۵ دقیقه‌ای (برای همان حساب و IP)، و محدودیت تعداد پیامک از هر IP. اپ پیام و کپچا و زمان قفل را از پاسخ سرور نشان می‌دهد.

نشست فقط در حافظه است: با هر بار باز کردن اپ (یا برگشتن پس از بیش از یک دقیقه) دوباره ورود لازم است. هر کاربر فقط روی یک گوشی وارد می‌ماند؛ ورود روی گوشی دیگر، گوشی قبلی را خارج می‌کند. توکن ۱۵ دقیقه اعتبار دارد و تا وقتی اپ باز است خودکار تمدید می‌شود. توکن هیچ‌جا ذخیره نمی‌شود؛ نام کاربری یا شماره همراه آخرین ورود برای راحتی پیش‌فرض می‌شود.

### ورود با اثر انگشت

پس از ورود موفق با رمز عبور، اگر گوشی اثر انگشت (یا بیومتریک «قوی» دیگری) دارد، اپ می‌پرسد «دفعه‌های بعد با اثر انگشت وارد شوید؟». با تأیید و تشخیص اثر انگشت، رمز با یک کلید AES در Android Keystore رمزگذاری و ذخیره می‌شود. این کلید:

- فقط بلافاصله پس از تشخیص اثر انگشت قابل استفاده است و از گوشی خارج نمی‌شود؛
- با اضافه یا حذف شدن اثر انگشتی در گوشی خودبه‌خود از بین می‌رود (ورود با اثر انگشت غیرفعال و پیام داده می‌شود)؛
- نسخه پشتیبان ندارد (backup اپ خاموش است).

از آن به بعد صفحه ورود (هنگام باز کردن اپ یا برگشتن پس از وقفه) خودش اثر انگشت را می‌خواهد و با همان API ورود رمزی وارد می‌شود؛ پس همه محدودیت‌های سرور (کپچا، قفل، یک گوشی) به همان شکل اعمال می‌شوند. پس از «خروج از حساب» دستی، درخواست خودکار نمی‌آید و دکمه «ورود با اثر انگشت» در صفحه ورود هست.

- رمز در وب عوض شود: اولین ورود با اثر انگشت خطا می‌گیرد، رمز ذخیره‌شده پاک و پس از ورود با رمز جدید دوباره پیشنهاد می‌شود.
- «الان نه»: برای همان حساب دوباره پرسیده نمی‌شود؛ از کلید «ورود با اثر انگشت» در پایین صفحه اصلی دوباره روشن می‌شود (در ورود بعدی با رمز پیشنهاد می‌شود). خاموش کردن همان کلید رمز ذخیره‌شده را پاک می‌کند.
- تغییر کارفرما همه این اطلاعات را پاک می‌کند. فقط یک حساب در هر گوشی ذخیره می‌شود.

## پس از ورود

اپ فقط برای **پرسنل** است: سرور ورود ادمین و کاربران «کارفرما/منابع انسانی» را رد می‌کند و اگر نوع حسابی بعداً عوض شود، در درخواست بعدی از اپ خارج می‌شود.

منوی کناری (دکمه منو در نوار بالا؛ در چیدمان راست‌به‌چپ از سمت راست باز می‌شود) همان منوی پنل کاربری وب است:

| بخش | API در فیشی‌نو | توضیح |
|---|---|---|
| خانه | `GET /api/v1/home` | مشخصات، کارهای معوقه (با دکمه رفتن به همان بخش پروفایل)، ۵ سند و ۵ درخواست آخر |
| اسناد | `GET /reports` | فهرست کامل؛ تا تکمیل پیش‌نیازها (توافقنامه، مدارک الزامی) مخفی است |
| درخواست‌ها | `GET /requests`، `/requests/{id}`، `/forms` | فهرست، جزئیات و نظر بررسی‌کننده‌ها، دریافت PDF؛ ثبت درخواست جدید از فرم‌های مجاز محل خدمت (متنی، عددی، ریالی، انتخابی؛ فرم آنلاین در مرورگر) |
| خبرنامه | `GET /news`، `/news/{id}` | فهرست با تصویر، متن، گالری و پیوست‌ها |
| پروفایل | `/profile/…` | همه بخش‌های پروفایل وب: رمز ورود (و کلید ورود با اثر انگشت)، شماره موبایل با کد پیامکی و شاهکار، امضا (رسم با انگشت)، تصویر کاربر، مدارک، اطلاعات فردی و بانکی (با تأیید مدیر)، اتصال بله، توافقنامه با کد پیامکی، ورودهای اخیر |

قواعد همان وب است و در خود فیشی‌نو اجرا می‌شود؛ تا شماره همراه یا تغییر رمز اول انجام نشده، بخش‌های دیگر پروفایل تغییری نمی‌پذیرند. متن‌های HTML (خبر، درخواست، توافقنامه) به‌صورت متن نمایش داده می‌شوند و هیچ اسکریپتی اجرا نمی‌شود. تصاویر و فایل‌ها با توکن کاربر دریافت می‌شوند، فقط در حافظه و پوشه موقت اپ می‌مانند و با خروج از حساب پاک می‌شوند.

باز کردن و امضای سند (فیش و قرارداد) در مرحله بعد اضافه می‌شود.

## نسخه رسمی و به‌روزرسانی داخل اپ

اپ (نسخه تست و بعداً نسخه رسمی) هنگام باز شدن، حداکثر هر ۱۲ ساعت یک بار، آخرین Release این مخزن را از GitHub می‌خواند؛ نسخه تست فقط فایل `fishino-test-*.apk` و نسخه رسمی فقط `fishino-*.apk` را برمی‌دارد. اگر نسخه جدیدتری باشد، پیشنهاد به‌روزرسانی می‌دهد و پس از تأیید کاربر:

1. فایل APK را دانلود می‌کند و حجم و SHA-256 آن را با مقدار اعلام‌شده GitHub مقایسه می‌کند؛
2. بررسی می‌کند که فایل همین اپ، نسخه جدیدتر و با **همان کلید امضا** باشد؛
3. صفحه نصب اندروید را باز می‌کند تا کاربر تأیید کند (بار اول اندروید ۸ به بالا اجازه «نصب از این منبع» را می‌پرسد).

کاربر همیشه می‌تواند «بعداً» بزند؛ هیچ نصبی بدون تأیید او انجام نمی‌شود. «بررسی به‌روزرسانی» در صفحه اصلی هم هست. نسخه‌های دیباگ (ساخته‌شده در Android Studio) به‌روزرسانی را بررسی نمی‌کنند.

### انتشار نسخه جدید

در GitHub یک Release با تگ `v1.2.3` منتشر کنید (Releases ← Draft a new release ← تگ جدید ← Publish release). ورک‌فلوی «Release APK» حدود ۵ دقیقه بعد فایل APK را به همان Release پیوست می‌کند:

| وضعیت | فایل پیوست | توضیح |
|---|---|---|
| کلید امضای رسمی هنوز تعریف نشده (فعلاً) | `fishino-test-1.2.3.apk` | **نسخه تست**: شناسه `rdsco.fishino.app.test`، نام «فیشی‌نو (تست)»؛ فقط بار اول دستی نصب می‌شود و بعد از آن خودش از هر Release جدید به‌روز می‌شود |
| کلید امضای رسمی تعریف شده (پایین) | `fishino-1.2.3.apk` | نسخه رسمی `rdsco.fishino.app`؛ اپ‌های نصب‌شده آن را پیشنهاد می‌دهند |

نسخه تست با کلید عمومی `app/test-signing/fishino-test.jks` امضا می‌شود که عمداً در مخزن است و فقط برای همان شناسه تست به کار می‌رود.

تا پیوست شدن APK، اپ‌ها نسخه جدید را پیشنهاد نمی‌دهند. Release را **Pre-release** علامت نزنید؛ اپ‌ها فقط آخرین Release عادی را می‌بینند. برای گوشی‌های تست فقط از فایل Releaseها استفاده کنید، نه Artifact صفحه Actions (شماره نسخه آن ۱ است و روی نسخه Release نصب نمی‌شود). در هر دو حالت تگ باید شکل `v1.2.3` داشته باشد و `versionCode` از روی آن ساخته می‌شود (`major*10000 + minor*100 + patch`)، پس minor و patch باید زیر ۱۰۰ باشند. Pre-release و Draft به کاربران پیشنهاد نمی‌شوند.

### کلید امضای رسمی (یک بار، قبل از انتشار برای کاربران واقعی)

اندروید فقط به‌روزرسانی‌ای را نصب می‌کند که با **همان کلید** نسخه نصب‌شده امضا شده باشد. این کلید را یک بار روی سیستم خودتان بسازید و نسخه پشتیبان امن از آن نگه دارید؛ اگر گم شود، کاربران باید اپ را حذف و دوباره نصب کنند.

```bash
keytool -genkeypair -v -keystore fishino-release.jks -alias fishino \
  -keyalg RSA -keysize 4096 -validity 36500 \
  -dname "CN=Rahkar Digital Sharif, O=RDSCO, C=IR"
base64 -w0 fishino-release.jks > fishino-release.jks.b64   # macOS: base64 -i fishino-release.jks -o fishino-release.jks.b64
```

سپس در **Settings → Secrets and variables → Actions** مخزن:

| نوع | نام | مقدار |
|---|---|---|
| Secret | `ANDROID_KEYSTORE_BASE64` | محتوای `fishino-release.jks.b64` |
| Secret | `ANDROID_KEYSTORE_PASSWORD` | رمز keystore |
| Secret | `ANDROID_KEY_ALIAS` | `fishino` |
| Secret | `ANDROID_KEY_PASSWORD` | رمز کلید (معمولاً همان رمز keystore) |
| Variable | `FISHINO_DIRECTORY_PUBLIC_KEY` | کلید عمومی سامانه مدیریت (اگر در `gradle.properties` نیست) |

فایل `.jks` و رمزها هرگز در مخزن قرار نگیرند. اگر نسخه‌ای از قبل با کلید دیگری (مثلاً دیباگ) روی گوشی‌ها نصب شده، یک بار باید حذف و نسخه رسمی نصب شود.

### محدودیت‌ها

- مخزن باید **عمومی** بماند؛ اپ بدون توکن از API عمومی GitHub می‌خواند. GitHub برای هر IP ساعتی ۶۰ درخواست اجازه می‌دهد؛ اگر در یک شبکه بیش از این تعداد گوشی هم‌زمان بررسی کنند، بقیه بی‌صدا دفعه بعد بررسی می‌کنند.
- دانلود مستقیم از GitHub است؛ اگر در شبکه کاربر GitHub کند یا محدود باشد، دانلود ممکن است با خطا مواجه شود (پیام «تلاش دوباره» نمایش داده می‌شود).
- اگر اپ را در گوگل‌پلی یا بازار منتشر کنید، به‌روزرسانی داخل اپ خلاف قوانین آن فروشگاه‌هاست؛ برای آن نسخه `fishino.updateRepo` را خالی بگذارید.

## ساختار

```text
app/src/main/java/rdsco/fishino/app/
├── FishinoApp.kt, AppContainer.kt   راه‌اندازی و وابستگی‌ها
├── MainActivity.kt                  انتخاب صفحه: ورود کد یا خانه
├── employer/                        کد کارفرما، تماس با سامانه مدیریت، بررسی امضا، ذخیره
├── auth/                            API ورود فیشی‌نوی کارفرما، نشست در حافظه، استخراج کد پیامک، رمز اثر انگشت
├── panel/                           API پنل کاربر: خانه، اسناد، درخواست‌ها، خبرنامه، پروفایل
├── update/                          آخرین Release در GitHub، دانلود و بررسی APK، نصب
└── ui/
    ├── onboarding/                  ورود کد و تأیید نام کارفرما
    ├── login/                       صفحه ورود (رمز عبور / کد پیامکی، کپچا، قفل موقت، خواندن پیامک)
    ├── shell/                       نوار بالا و منوی کناری، مسیر صفحه‌ها
    ├── home/                        صفحه اصلی و فهرست اسناد و درخواست‌ها
    ├── news/, requests/, profile/   خبرنامه، ثبت و جزئیات درخواست، بخش‌های پروفایل
    ├── common/                      اجزای مشترک، تصویر با توکن، نمایش HTML
    ├── update/                      پنجره به‌روزرسانی
    └── theme/                       رنگ‌ها، فونت، راست‌به‌چپ
```

فونت وزیرمتن تحت مجوز OFL است (`FONT-LICENSE-Vazirmatn.txt`). آیکن فروشگاه (۵۱۲ پیکسل) در `app/src/main/ic_launcher-playstore.png` است.
